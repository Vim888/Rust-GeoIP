# rust-geoip

[English documentation](README.md)

Служба определяет страну, город, ASN, организацию и провайдера для IPv4 и IPv6. Она держит десять баз GeoIP Legacy в памяти и отвечает через Unix-сокет. IP посетителей обрабатываются на сервере сайта.

**Более чем на 1 000% быстрее стандартной CLI-утилиты GeoIP** в обоих тестах на 510 IP, даже с новым сокетом на каждый адрес. По медиане поиск ускорился в **162 раза на Linux-сервере** и в **13,3 раза на Debian 13 под QEMU**. [Результаты тестов](#результаты-тестов)

## Поиск IP при каждом входящем соединении

На тестовом сервере запуск `geoiplookup` или `geoiplookup6` для каждого IP занимал **2 540,6 мкс** по медиане. Та же операция через Rust-службу занимала **15,7 мкс** с новым Unix-сокетом и **8,1 мкс** при повторном использовании соединения. Время запроса к службе включает получение и разбор JSON клиентом.

Служба уже запущена, а базы находятся в памяти. При обращении к внешнему RPC каждый поиск требует ещё и сетевого обмена с поставщиком. Его задержка зависит от маршрута и времени ответа сервера. Внешние RPC в этом тесте не измерялись.

## Зависимости

| Для чего | Что требуется на Debian 13 |
| --- | --- |
| Сборка из исходников | Rust 1.85+, Cargo, инструменты сборки C (`build-essential`) и заголовки GeoIP Legacy (`libgeoip-dev`). Версии Rust-зависимостей Cargo берёт из `Cargo.lock`. |
| Работа службы | Linux с systemd, Unix-сокет и библиотека `libGeoIP.so.1` (`libgeoip1t64`, устанавливается вместе с `libgeoip-dev`). Нужны все десять файлов баз Legacy. |
| Установка и обновление баз | Права root для установки, Bash, GNU coreutils, `getent` (`libc-bin`), `useradd` и `groupadd` (`passwd`), `runuser` и `flock` (`util-linux`). Для обновления нужны `curl`, `ca-certificates`, `gzip` и доступ к зеркалу по HTTPS. |
| Примеры и проверка | PHP 8+ для примера подключения, `netcat-openbsd` для ручного запроса, Python 3 и `geoip-bin` для сверки результатов. |

**Служба и пример на PHP работают без Memcached.** libGeoIP загружает все десять баз в память процесса в режиме `GEOIP_MEMORY_CACHE`. Сервер Memcached и PHP-расширение `memcached` нужны только в том случае, если сайт использует их для собственного кэша.

## Установка на Debian 13

Скачайте ZIP с GitHub и распакуйте его или клонируйте репозиторий. Выполните команды из каталога с `Cargo.toml`. Сборка выполняется от обычного пользователя.

```sh
sudo apt update
sudo apt install cargo rustc build-essential libgeoip-dev ca-certificates curl gzip util-linux netcat-openbsd
cargo build --release --locked
sudo bash install.sh
sudo rust-geoip ping
printf '8.8.8.8\n2001:4860:4860::8888\n' | sudo nc -N -U /run/rust-geoip/lookup.sock
```

Установщик создаёт пользователя `rust-geoip`, загружает и проверяет базы в `/var/lib/rust-geoip`, включает автозапуск и дожидается ответа службы. Команда `ping` выводит дату старейшей базы в памяти. Тестовый комплект занимал около 135 МиБ на диске и около 140 МиБ в оперативной памяти. При перечитывании в памяти одновременно находились два комплекта, пик составил 286 МиБ. На диске при обновлении должно хватать места для обоих комплектов и распаковываемого архива.

## Подключение сайта

Доступ к сокету получает группа `rust-geoip`. Добавьте в неё пользователя, под которым выполняется код сайта, и перезапустите его рабочие процессы. Для стандартного пула PHP-FPM в Debian 13:

```sh
sudo usermod -aG rust-geoip www-data
sudo systemctl restart php8.4-fpm
printf '8.8.8.8\n' | sudo -u www-data nc -N -U /run/rust-geoip/lookup.sock
```

Для PHP 8+ скопируйте файл [examples/lookup.php](examples/lookup.php) рядом с кодом сайта:

```php
require_once __DIR__ . '/lookup.php';

$geo = geoipLookup($_SERVER['REMOTE_ADDR'] ?? '');
$country = $geo['country_code'] ?? null;
```

При неверном адресе или недоступности службы функция возвращает `null`. Если перед сайтом стоит обратный прокси, настройте веб-сервер так, чтобы адрес посетителя в `REMOTE_ADDR` определялся через доверенный прокси.

Из другого языка откройте `/run/rust-geoip/lookup.sock`, отправьте числовой IP и перевод строки LF, прочитайте одну строку JSON. Соединение можно использовать повторно. Предел строки с LF — 64 байта, тайм-аут простоя — 10 секунд. Ответ содержит `country_code`, `country_name`, `city`, `asn`, `organization`, `isp`. Если записи в конкретной базе нет, значение поля равно `null`. Для неверного IP ответ — `{"error":"invalid_ip"}`.

## Обновление и диагностика

```sh
systemctl list-timers rust-geoip-update.timer
sudo systemctl start rust-geoip-update.service
sudo rust-geoip ping
sudo -u rust-geoip rust-geoip validate /var/lib/rust-geoip
sudo journalctl -u rust-geoip -n 30 --no-pager
```

Установщик включает еженедельный таймер systemd. Для ручного режима отключите его командой `sudo systemctl disable --now rust-geoip-update.timer`. Скрипт проверяет все десять файлов, атомарно переключает каталог баз и просит работающую службу перечитать их. При сбое скачивания прежний комплект остаётся на диске, причина видна в `journalctl -u rust-geoip-update`. При ошибке перечитывания служба продолжает отвечать из прежних баз в памяти. После устранения причины выполните `sudo systemctl reload rust-geoip`. Перечитывание доступно владельцу службы и root.

Чтобы выбрать своё HTTPS-зеркало, укажите `GEOIP_SOURCE_URL=https://mirror.example.org/geoip` в `/etc/default/rust-geoip` перед первой установкой или следующим обновлением. На зеркале должны лежать десять архивов в том же формате и с теми же именами, что у поставщика.

## Результаты тестов

### Замеры на Linux-сервере — Intel Core i7-14700F, 64 ГБ DDR5

**Готовая Rust-служба и стандартная утилита.** Последовательный прогон на одних и тех же 510 адресах IPv4 и IPv6 дал совпадающие результаты по пяти базам соответствующего семейства. Клиент службы измерял время от отправки запроса до разбора JSON, включая открытие сокета в сценарии с новым соединением. Для CLI время включало запуск процесса.

| Способ поиска | Медиана, мкс | 95-й процентиль, мкс | Ускорение относительно CLI |
| --- | ---: | ---: | ---: |
| `geoiplookup` / `geoiplookup6`, новый процесс на каждый IP | 2 540,6 | 2 855,6 | 0% (база) |
| Rust, новое соединение на каждый IP | 15,7 | 20,2 | **+16 082%** |
| Rust, открытое соединение | 8,1 | 15,4 | **+31 265%** |

Ускорение рассчитано по медианам одного прогона по формуле `(время CLI / время метода − 1) × 100%`. Если поиск занимает вдвое меньше времени, его скорость выше на 100%.

**Сравнение реализаций службы.** Прототипы на C++, Python, Go и Rust постоянно работали в памяти и использовали одну и ту же библиотеку `libGeoIP` и десять баз. Полные ответы совпали на 1 507 входных значениях. После прогрева в каждом режиме выполнили по 24 112 запросов с одним клиентом и по 96 448 с восемью. В каждой ячейке указаны **медиана / 95-й процентиль в микросекундах**, включая разбор JSON клиентом.

| Клиенты и соединения | C++ | Python | Go | Rust |
| --- | ---: | ---: | ---: | ---: |
| 1 клиент, открытый сокет | 12,9 / 16,1 | 25,8 / 33,8 | 11,0 / 18,4 | 9,4 / 12,1 |
| 1 клиент, новый сокет на IP | 18,1 / 36,2 | 76,3 / 87,8 | 19,9 / 51,5 | 15,7 / 20,8 |
| 8 клиентов, открытые сокеты | 38,9 / 61,3 | 156,7 / 170,1 | 26,0 / 58,3 | 21,0 / 31,1 |
| 8 клиентов, новый сокет на IP | 68,0 / 93,0 | 416,3 / 456,8 | 51,5 / 97,1 | 46,0 / 61,1 |

**Замер из PHP.** При новом соединении с Rust-службой медиана составила около 14 мкс, а 99-й процентиль — от 20 до 48 мкс в разных прогонах. Сама обработка IP внутри службы занимала около 3 мкс. В отдельном тесте один поток обработки достиг примерно 140 000 запросов/с при насыщении. Служба также приняла 20 000 соединений без отправки запросов и продолжила отвечать.

### Текущая версия для Debian 13 — 4 vCPU x86-64, 3 ГиБ RAM

**Имитация слабого VPS.** Тест выполнялся в виртуальной машине QEMU с программной эмуляцией процессора (TCG, модель CPU `max`).

Для **510 из 510** адресов IPv4 и IPv6 результаты совпали с `geoiplookup` или `geoiplookup6` на тех же файлах баз. При открытии нового сокета и при повторном использовании соединения служба вернула одинаковые значения JSON.

| Как выполнялся запрос | Медиана, мкс | 95-й процентиль, мкс | Ускорение относительно CLI |
| --- | ---: | ---: | ---: |
| Отдельный процесс CLI на адрес | 11 759,5 | 13 485,0 | 0% (база) |
| Из Python к Rust-службе, новое соединение | 885,0 | 1 271,6 | **+1 229%** |
| Из Python к Rust-службе, открытое соединение | 507,1 | 844,5 | **+2 219%** |

После перезагрузки запустились служба и еженедельный таймер. При недоступном зеркале сохранился прежний комплект баз. Успешное обновление переключило комплект с сохранением PID службы.

Чтобы получить цифры для своего сервера, выполните команды из каталога проекта между обновлениями баз. Скрипт проверяет 10 фиксированных и 500 воспроизводимых псевдослучайных адресов и выводит медиану и 95-й процентиль для каждого способа запроса. [Скрипт проверки](tests/check-lookup.py)

```sh
sudo apt install python3 geoip-bin
sudo python3 tests/check-lookup.py
```
